Live Cloud Architecture & AI

Python  •  AWS Lambda  •  DynamoDB  •  CloudWatch  •  Claude API

The live conversational assistant running in the bottom-right corner of this page—built to answer recruiter questions at any hour and never run up a bill.

Problem

Recruiters visit at all hours with questions about experience, while an unprotected public LLM endpoint is an easy way to run up a surprise bill.

Built

A zero-dependency Python Lambda calling the Claude API, locked to portfolio topics with per-IP daily DynamoDB limits, input/output caps, and origin-locked CORS.

Result

Live recruiter assistant with a hard cost ceiling by design: 20 requests/IP/day, 500-character inputs, 300-token replies, and CloudWatch telemetry.

Phase 1: Production Infrastructure & Cost Guardrails

Powered by a zero-dependency Python AWS Lambda handler utilizing native urllib and boto3 to invoke Anthropic's Claude API without deployment bloat. Protected against abuse via atomic daily IP rate-limiting in DynamoDB (ip_date composite keys), reserved concurrency caps, strict origin-locked CORS policies, and full CloudWatch telemetry.

Phase 3: Architecture & Deployment Strategy

Current Infrastructure (Bootstrapped): To optimize for rapid prototyping and zero-cost deployment, the application utilizes Render for hosting the Flask REST API and React frontend, paired with Neon for serverless PostgreSQL. While this allows for fast iteration, it introduces cold-start latency and network hops between disparate cloud providers.

The Scale-Up Plan (Enterprise Architecture): With an active user base, the infrastructure would be migrated entirely into a single AWS Virtual Private Cloud (VPC) to minimize latency. The frontend would be distributed via CloudFront (CDN), the Flask API containerized on AWS ECS (Fargate) for elastic auto-scaling, and the database migrated to Amazon Aurora PostgreSQL to support high-throughput read replicas.
